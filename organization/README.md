# 组织架构

本目录是依据 [`../DIRECTIVE.md`](../DIRECTIVE.md) 制定的具体组织规章，展开各部的
职责分工、工作接口和实施边界。`DIRECTIVE.md` 规定根本层级、权责原则及不可违背的
约束；本目录不得与之冲突。

## 两个组织维度

- **职能层级**：部 → 司 → 处 → 科 → 组。单位按实际职责设置，不要求每条组织链都
  机械包含全部级别。
- **地域层级**：省 → 市 → 县 → 乡 → 村。它表示覆盖区域，与职能组织树分开登记；
  不能仅凭层级名称推定相应地区已有团队、人员或执行能力。

## 部门职责和接口

| 单位 | 职责 | 输入/输出边界 |
|---|---|---|
| 模块一：监测获取分析部（M1部委） | 资源发现、跟踪与分析；巡检制度、MIU 登记、证据和异常闭环 | 资源分析与巡检结论分开登记；资源变更在 24 小时内交巡检司评估 |
| 模块二：字幕生成视频刻录部署部 | 消费上游已选定的视频/字幕；生成字幕、刻录成片、质检，并执行约定的站点/归档部署 | 输出经质检的成品及报告；不自行决定来源或上传到外部镜像平台 |
| 模块三：上传平台部 | 接收模块二验收通过的成品；维护上传平台适配、执行上传、记录状态与链接回执 | 不修改成品内容、不代替模块二验收；每个平台结果应可独立核验 |
| PDCA部 | 协调计划、执行跟踪、检查评估、纠正措施和复盘 | 责任模块保留原始执行与验收结论；PDCA 检查证据并跟踪闭环，不改写事实 |

M1部委是模块一的简称；资源获取分析司和定期巡检司均隶属 M1部委，司级单位不得在
组织图或权责表中误列为与 M1部委平级。

模块二的站点/归档部署指本仓库 Pages、Release 等成品发布流程；模块三的平台上传指
Filebin、GoFile 等外部目标平台。两者可以共享模块二已验收的成品，但工作流、成功
证据与失败结论分别记录，不得互相代替。详细职责分别见
[`module-3-platform-upload.md`](module-3-platform-upload.md) 和 [`pdca.md`](pdca.md)。

## 组织登记和实现状态

架构规章描述职责，不代表对应部门、地理分支、平台连接器或自动化已经上线。当前可
核验的代码、工作流、登记与缺口，以相应 registry、实现文件和运行证据为准。地域
层级只有在明确登记责任主体、覆盖范围与证据渠道后才视为已建立。
