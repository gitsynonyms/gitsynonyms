# 组织架构

本目录是依据 [`../DIRECTIVE.md`](../DIRECTIVE.md) 制定的**具体组织规章制度**，
负责展开部门设置、职责分工、内部流程、接口和实施细则。`DIRECTIVE.md` 是规定根本
层级、权责原则和不可违背约束的**宪法性最高指示**；本目录不得与之冲突。

授权范围内调整部门内部设置、职责细节或流程时，修订本目录及相关实施文件即可；
只有改变根本层级、授权边界或宪法性原则时，才需要总控同步修订 `DIRECTIVE.md`。

## 职责接口

- **资源获取分析司**维护资源清单、采集器映射与资源变化；不负责视频字幕刻录。
- 信息差公示处是资源获取分析司内部的研究与发布单元；职责、边界和实现状态见
  [`resource-acquisition-analysis.md`](resource-acquisition-analysis.md)。
- **定期巡检司**负责巡检制度、最小可巡检单元、证据与异常闭环。
- **模块2：视频处理部**只接收上游已经选定的视频和字幕任务；不得自行替代上游
  选择来源、判定资源重要性或更改巡检结论。
- **字幕时间精确刻录司**负责字幕源、时间精度、模型/平台横向评估和可读性研究；
  第三方 API 调用须遵守对应服务条款，并在任务开始前明确音视频会发送给哪些服务。
- 模块2的五个职责单元及精度、画面处理要求，见
  [`module-2-video-processing.md`](module-2-video-processing.md)；各处室的研究依据、
  量化方案与实现边界见
  [`subtitle-office-research.md`](subtitle-office-research.md)。

## 全流程工作分支

跨段端到端问题（monitor → download → burn → publish）统一在 `全流程` 分支复现、
修复与验证；该分支的使用制度、失败阶段判定、交接件验收与分支操作约定见
[`full-pipeline.md`](full-pipeline.md)。它是工作分支制度，不新增部门，也不改变
巡检、资源或发布授权。

## 规章与实现状态

本目录中的组织职责规定与代码实现状态是两类事实，不代表其中列出的每项制度都已
自动化。模块2的职责映射、当前代码位置和未完成要求必须分开说明；不得仅凭组织规章
或架构登记宣称功能已上线。
