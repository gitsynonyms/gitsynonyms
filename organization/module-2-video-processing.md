# 模块2：视频处理部

## 职责边界

模块2处理**已经由上游选定**的视频和字幕。输入至少要能定位源视频、字幕目录、
目标语言和输出目录；模块2不负责频道扫描、视频选择、资源登记或上游巡检。

## 五个职责单元

| 子部门 | 职责 | 目标实现入口 |
|---|---|---|
| 素材接收组 | 读取上游选择清单；校验视频与字幕目录、语言对、文件完整性和输出路径 | `video_processing.py` |
| 字幕时间精确刻录司 | 发现并保留 YouTube 七种字幕格式；以 JSON3 逐词时间为主，结合其余格式交叉校验、对齐与回退；构造高精度时间轴并生成 ASS | `subtitle_timing.py` |
| 字幕区判定组 | 检测片源字幕区是否被横幅遮挡；有遮挡时启用半透明总统蓝背景，无横幅的干净片源则直接显示字幕、不画背景框 | `video_processing.py` |
| 刻录渲染组 | 单遍 libass 硬字幕；生成 540p 预览和封面；成功后原子替换最终输出，避免留下半成品 | `video_processing.py` |
| 质检交接组 | 使用 ffprobe 校验输出；检查字体与缺字；输出 `BURN.json`、`TIMING.json` 及可复核的处理结果 | `video_processing.py` |

## 时间轴精度规则

1. 下载并保留以下全部格式：`vtt`、`srt`、`ttml`、`srv3`、`srv2`、`srv1`、`json3`。
   JSON3 的逐段 `tOffsetMs` 是主要逐词时间来源；其他格式用于校验、补齐和回退，
   不得静默覆盖更精确的有效时间。
2. 时间计算应保留来源提供的原始精度，优先使用整数 tick 或精确有理数运算，避免
   二进制浮点舍入；记录来源精度、选用来源和量化误差。没有来源证据的亚毫秒或纳秒
   只能标为推算值，不能伪装成 YouTube 原始精度。
3. **当前不能承诺“优于毫秒”或纳秒级字幕。** 仓库现有 JSON3 解析读取
   `tStartMs`、`dDurationMs`、`tOffsetMs`（毫秒字段），现有 ASS 时间戳写出保留两位
   小数，即厘秒（10 毫秒）量化。因此目前产物的 ASS 时间精度甚至低于毫秒；要达到
   更高的 ASS 时间精度，必须另行验证目标播放器/libass 对非标准细分时间戳的支持，
   或改用可承载该精度的输出格式并完成兼容性测试。在此之前不得宣称已达到该要求。
4. `TIMING.json` 应保留融合前后的精确整数时间、原始字幕格式、逐词来源、舍入/
   量化差值和冲突处理理由，使时间轴可审计。

## 字幕区与画面规则

- **检测到横幅遮挡字幕区**：选择不覆盖关键信息的位置，绘制半透明总统蓝
  `#0F1647` 背景框，再显示字幕；透明度须可配置并写入 `BURN.json`。
- **确认是干净片源**：不绘制背景框或遮挡区，只显示字幕。
- **检测结果不确定**：在质检记录中标为 `unknown` 并要求复核；不得静默按“干净”
  处理，也不得默认铺设不透明背景。
- `BURN.json` 应记录检测结论、置信信息、区域坐标、所用样式及渲染参数。

## 实现现状与差距

本节区分组织职责目标与仓库中已经存在的代码，不以计划中的模块名暗示代码已落地。

| 能力 | 当前代码证据 | 状态 |
|---|---|---|
| 七种字幕格式及 JSON3 优先级 | `scripts/download_youtube_bilingual_srt.py` 中的 `CAPTION_FORMATS`、`CAPTION_PARSERS`、`CAPTION_PRECISION_ORDER` | 已有基础实现 |
| JSON3 毫秒字段解析与逐词切分 | 同文件 `parse_json3()`；使用浮点秒数 | 已有，但需改为精确整数时间运算 |
| ASS 时间戳与字幕样式 | 同文件 `ass_timestamp()`、`build_ass()`；时间写为两位小数 | 已有；当前量化为 10 毫秒 |
| 总统蓝背景样式 | 同文件 `BOX_STYLES["presidential-blue"]` | 有可选样式；尚无横幅自动检测和按片源切换 |
| 素材接收、渲染、预览/封面、原子替换、ffprobe、交接清单 | 处理流程目前集中在 `scripts/download_youtube_bilingual_srt.py`；工作流调用 `--box-display always`、`--burn-in` | 所列能力尚未按目标实现 |
| 独立模块文件 | `video_processing.py`、`subtitle_timing.py` 当前不存在 | 目标拆分，待实施 |

因此，组织档案先固定五个职责边界和验收要求；只有对应代码、测试和工作流均完成后，
才能把相关能力的状态改为“已实现”。当前工作流始终显示背景框的行为也不满足
“横幅才显示总统蓝框、干净画面直出”的目标，不能作为该目标已上线的证据。

## 交接验收

处理任务完成时，至少应交付最终 MP4、ASS、`BURN.json`、`TIMING.json` 和质检结果。
失败时保留明确错误与失败阶段，不将部分视频作为成功输出；最终文件应在全部校验通过
后原子替换。
